# tools/ — 平台之外的离线小工具

这个目录放**不参与压测运行、只对产物做二次加工**的独立脚本。它们不是 `scripts/` 下的压测脚本:平台不会发现、不会注册、不会在设备列表里出现(平台只 glob `scripts/*.py`,且跳过 `_` 开头的文件)。它们也不需要设备、不需要 ADB,拿归档下来的 csv 就能跑。

---

## ntc_convert.py — NTC 原始 ADC 计数 → 摄氏度 + 温度曲线图

### 为什么换算不写在 perf_monitor 里

`perf_monitor` 采到的是**原始 ADC 计数**,而且它在 `samples.csv` 表头里明说了(`# ntc_unit=raw_adc`)。换算**故意不放进采集脚本**,因为驱动换算的常数是**按项目变的**:换一块板子,分压电阻、B 值、ADC 满量程都可能不一样。把某一块板的常数焊死进采集脚本,换板子就会**静默算错**,而且错得没有任何提示。

所以分工是:

| | |
|---|---|
| `perf_monitor`(采集) | 落**原始计数**,声明单位,每个节点一列 |
| `tools/ntc_convert.py`(换算) | 拿该项目 profile 里的常数,把计数换成摄氏度 |

附带好处:归档的 `samples.csv` 跨项目、跨公式版本都还能对比 —— 因为它是原始值。

> 用户 2026-09-20 原话:「可以 perf 只输出 adc 的 excel,然后调用另外一个工具脚本来换算,然后这个工具脚本的目录存一下每个项目不同的一些参数,目前看起来只是一些参数值可能不一样,但是公式是一样的」

### 它现在会被 perf_monitor **自动调用**(v2.14.0)

跑完一次压测,`perf_monitor` 收尾时会自动跑一次换算 —— **只要这次真的采到了 NTC**。产物和手工跑完全一样,落在 `samples.csv` 旁边,然后随报告一起进 `archive/`:

- 控制台多几行 `[ntc] ...`,写明**用的哪个 profile**、输入是哪个 csv、两个产物落在哪;
- **这次没勾选「NTC 节点温度」**(或一次都没读成功)→ 完全不出现 `[ntc]` 行,也不会多出文件;
- 工具缺失 / 超时 / profile 名不存在 → 只多一行 `[ntc] no conversion: <原因>`,**运行本身照常结束、结论不变**;
- **例外:硬停(SIGKILL)不触发换算**(`finish()` 根本没跑),归档里只有原始 ADC,要手工补一次(见 [../TODO.md](../TODO.md) §6.21)。

**这个自动调用要用哪个 profile,是前端可配参数 `ntc_profile`**(参数弹窗里选,每台设备 × 每个脚本各自保存),默认 `9660_P53_2G`。

### 用法

```bash
# 基础:把某个 samples.csv 换成摄氏度,输出写在它旁边
python tools/ntc_convert.py reports/stress-test/perf/perf_XXX_20260920_181551.samples.csv

# 指定项目 profile / 指定输出位置
python tools/ntc_convert.py <samples.csv> --profile <项目名>
python tools/ntc_convert.py <samples.csv> --out D:\somewhere\temps.csv

python tools/ntc_convert.py <csv> --no-chart    # 只要 csv,不要图
python tools/ntc_convert.py <csv> --theme dark  # 图用深色(默认浅色)

python tools/ntc_convert.py --list-profiles   # 有哪些 profile
python tools/ntc_convert.py --selftest        # 自检(不需要设备、不需要数据)
```

**产出两个文件,都落在输入的旁边**(或 `--out` 指定的位置):

| 产物 | 说明 |
|---|---|
| `<原名>.temps.csv` | 摄氏度;原始计数一并保留 |
| `<原名>.temps.png` | 温度曲线图,150 dpi 的 PNG |

- **输入文件永不被修改、永不被移动** —— 归档属于产生它的那次运行。
- 输出已存在时会拒绝覆盖,加 `--force`。**一次运行产出这两个文件,`--force` 同时作用于两者** —— 新的 csv 配着旧的图,比没有图更糟。

控制台会打印每个通道的 `seen / fresh / avg / min / max / bad / oor`,**平均与极值只对 `fresh` 读数算**(见下),并顺便拿 profile 里的节点路径和 csv 表头里记的实际路径对一下,不一致就 `[warn]`。

> **图是可选依赖。** 它由 matplotlib 画,而 matplotlib **不是**这个工具的硬依赖:CSV 才是产物,图是另一半。没装 matplotlib 时工具**照常出 CSV**,只打一行 `[warn] no chart written: ...`。这**不会静默**跳过 —— 「CSV 好好的、图不见了」正是会让人白找一通文件的状态。

### 输出格式

在输入旁边生成一个 `<原名>.temps.csv`,**长这样**:

```
# PPTP ntc conversion v1 | tool=ntc_convert.py 1.3.1
# source=perf_XXX_20260920_181551.samples.csv
# profile=9660_P53_2G (E:\ProjectorPressureTest\tools\ntc_profiles\9660_P53_2G.ini)
# unit=celsius | ...
# formula=1/T = 1/T0 + ln((R_pull*adc/(SAR-1-adc))/R0)/B with T0=25C
# params=r_pull_k=4.7,4.7 r0_k=10,10 b=4010,4010 b_cold=3950,3950 b_switch_r=3588 comp=0,0 ...
t_sec,ntc_lcd_raw,ntc_led_raw,ntc_lcd_c,ntc_led_c,ntc_st,ntc_lcd_st,ntc_led_st
0.0,664,371,28.19,57.42,f,ok,ok
2.0,664,371,28.19,57.42,h,ok,ok
```

| 列 | 含义 |
|---|---|
| `ntc_lcd_raw` / `ntc_led_raw` | 原始计数,**原样保留** —— 换算结果永远可以复核 |
| `ntc_lcd_c` / `ntc_led_c` | 摄氏度,两位小数 |
| `ntc_st` | 源文件的通道状态字符(`f` 真实读数 / `h` 保持 / `n` 未到期 / `x` 读失败 / `a` 节点不在 / `d` 未采集) |
| `ntc_lcd_st` / `ntc_led_st` | **本工具的**逐通道换算状态 |

`ntc_lcd_st` / `ntc_led_st` 取值:

- `ok` —— 换算成功且落在 profile 声明的量程内
- `oor` —— 换算成功但**超出量程**(默认 -20~100 °C)。**只标记,不钳位**:超量程要么是真故障,要么是 profile 常数填错了,这两种都必须让人看见;钳掉就把后一种变成了一个看着合理的数
- `bad` —— 算不出温度(计数 ≥ 无效阈值、或 ≤ 0)
- `-` —— 源文件这一格本来就是空的

> `ntc_lcd_st` / `ntc_led_st` 这两列是有意加的:源文件的两个节点**共用**一个 `ntc_st`(一次 `cat pathA pathB` 只产生一个新鲜度),所以「一个节点读失败」在源文件里只能靠哪一格是空的来区分,那个状态字符本身分不出是哪一个。这里逐通道给出,补上了这个归因。

---

### 统计口径:只算 fresh

`avg / min / max` **只统计 `ntc_st == 'f'` 的真实读数**,不含 `h`(保持拍)。两条理由:

1. **`h` 拍是把上一个真实值抄一遍**,不是新观测。把它算进平均,等于按「机器静了多久」给一个值加权。
2. **要和报告对得上**。`perf_monitor` 的判定行里那个 `n=` 就是真实读数条数,平均也只对它算。用另一种口径会得到同一次运行的**两个不同的平均值**。

具体到 30 秒档:120 秒的跑批在 61 行数据里只有 **5 个** fresh 读数(其余 56 行是保持拍),所以 `n=5`,而不是 61。

> 这条口径直接决定了图长什么样:**跑得太短就没有曲线可画**。24 秒的跑批只有 **1** 个真实读数(图上就是一条平线);120 秒有 5 个;**要一条像样的温度曲线,单次跑 10 分钟以上**(约 20 个点)。这不是画图的问题,是 SLOW 档 30 秒一格决定的。

## 温度曲线图

图不是「顺便画一下」,它是一句**关于分辨率的陈述**,所以有两件事必须画对:

### 1. 阶梯,不是斜线

两个节点都在 **SLOW 档**,30 秒才采一次,采集侧把这次读数**保持**到下一次。零阶保持本来就是**分段常数**,阶梯就是它本来的形状。

**两点相隔 30 秒时画一条斜线,等于宣称中间每一个时刻的温度** —— 而那些时刻什么都没测过。所以:

- 线走**阶梯**(`where="post"`),值只在真实读数的那一刻跳
- **真实读数各打一个点**(带 2px 底色圆环,压在线上也看得清)
- 途中有读不到的格子,线**断开**而不是连过去;而且是**逐通道**断 —— 一个节点坏掉不会把另一个节点的线也拉断

点的条件是「采集侧标了 `f`」**且**「换算出了温度」:一次新鲜的读数如果计数超量程,那是一次**对坏读数的真实采样**,它既不该画成点,也不该悄悄消失(它会计入副标题的「N 个读数被判为无效」)。

**点密到分不开的时候,就不画点。**一个点要说「这里有一次读数」,就得让眼睛能把它和邻居分开 ——
需要它自己的直径**加上那圈描边**(描边骑在标记边界上,向内吃掉一半、向外占一半,所以**外沿直径** = `markersize + markeredgewidth` = 10 pt = **20.83 px**;而**可见点面**是 `markersize - markeredgewidth` = 6 pt)。
14.5 小时 / 1737 个读数摊在 1468 px 的绘图区上,**一个点 0.81 px** —— 差着二十多倍。
那种密度下那圈描边不再是分隔,而是**橡皮擦**:它会把底下的**台阶线**连同左右邻居的点面一起涂掉
(实测量到的绘图区彩色像素:线单独 **11930**,加上点只剩 **1974**)。
所以判不过就**整个不打点**,一条不少地留在 `*.temps.csv` 里;副标题改写成
「采样点密过屏幕像素,未画点」—— 少了点这件事不能让读者自己推。**逐通道判定**:
一个节点读数稀、另一个密,稀的那个照旧有点。

### 2. 读数密度写在副标题里

图上那行小字会写清 `每 30.0 秒一个真实读数 · N 个读数`。这个周期是**从数据里算出来的**(真实读数之间间隔的**中位数**),不是写死的常数 —— 中位数而不是均值或最小值,因为一次读失败会留下一个双倍间隔,而均值会把这个误差摊到其他所有间隔上。只有一个读数时它**不猜**,直接说「只有一个读数,看不出趋势」。

### 配色是算出来的,不是选出来的

两组配色都跑过**分类色板校验**(明度带、彩度下限、色盲可分辨度、常视可分辨度、与背景的对比度),全项通过:

| 主题 | 背景 | LCD / LED | 色盲可分辨度 | 常视可分辨度 |
|---|---|---|---|---|
| light(默认) | `#fcfcfb` | `#2a78d6` / `#eb6834` | ΔE 24.7 | ΔE 33.6 |
| dark | `#1a1a19` | `#3987e5` / `#d95926` | ΔE 26.8 | ΔE 31.8 |

**槽位顺序也是校验的一部分**:LCD 恒为 1 号槽,LED 恒为 2 号槽 —— 两个换位就会给读者已经学会的系列换色。自检**逐字钉住这六个色值**,所以「换个更好看的蓝」无法在不重跑校验的情况下落地。

默认浅色,因为它是要**贴进文档/Excel** 的那张;要看深色的(和平台里那些浏览器渲染的图同一个色调)加 `--theme dark`。深色是**自己一套**色值,不是把浅色反相。

### 图上有什么、没什么

其他规则:

- **单轴**。两个节点都是摄氏度,共用一个 Y 轴 —— **绝不做双 Y 轴**。代价是 LCD 那条会在图下方压得很平(它本来也就只有 0.1 °C 的波动),那是真实情况,不给它单独一根轴来放大。
- **图例必有**(两条线就不能只靠颜色区分),放在图下方而不是图内,不会压到线上。
- **只在线的末端直接标数值**(每条线一个数)。每个点都标数字等于没标;中间的值由坐标轴和 CSV 承担。
- 末端标的是**线的末端**,不是最后一个点 —— 收尾的保持拍会把线延伸到跑批结束,标在最后一个点上,数字就会落在最后一次**测量**发生的位置(跑得短的时候那是最左边,正好压住 Y 轴刻度)。

### 换算公式

逐字对应厂商参考实现 `transformNTCToTemp(int adcVal)`:

```
resister = R_pull * adc / (SAR_MAX - 1 - adc)      # NTC 的分压后电阻,欧姆
T_kelvin = 1 / ( 1/(273.15+25) + ln(resister/R0)/B )
T_c      = T_kelvin - 273.15 + TEMP_COMP
```

无温度可算的情况返回「没有值」而不是某个哨兵数:计数 ≥ 无效阈值(默认 1000,对应参考实现里的 `adcVal >= 1000` 分支)或 ≤ 0。

**B 值分两段,与参考实现一致**。参考实现在算出的分压电阻 **> 3588 Ω** 时把 `B` 从 `4010` 换成 `3950`;profile 里由 `NTC B VALUE COLD` / `NTC B VALUE COLD2` / `NTC B SWITCH R` 三个键承载。

3588 Ω 是一个**温度写成电阻的样子** —— 它正好是 3950 那条曲线上的 **50.00 °C**(同样的算式在 4010 曲线上解得 3532.8 Ω,所以 3588 只可能来自 3950 一侧)。规则读作:**冷于 50 °C 用 3950,50 °C 及以上用 4010**。比较的是**电阻**、用的是**严格大于**,因为参考实现也是在算出温度之前只拿得到电阻。

三个键**要么都给、要么都不给**。只给一半 → **报错**,不会半套用。都不给 = **单 B 换算**,这是 2026-09-21 之前所有 profile 的行为,对「实现里没有这段切换」的板子仍然正确。输出表头的 `b_cold=` / `b_switch_r=` 会把实际用的规则印出来(没有就写 `none`),归档的 csv 因此能自述它是按哪一种算的。

> 2026-09-20「以配置为准」那条裁决在 2026-09-21 **被推翻**了:厂商的实际实现拿到了 —— 那是一段**通篇字面量、完全不读配置**的 Java。板子上跑出任何一个温度,用的都是那些字面量,不是配置文件。见 `docs/DECISIONS.md` **D-64**(D-63 的旧裁决原文保留,加了推翻标记)。实际差别:这块板子 LCD 节点 **+0.045 ~ +0.053 °C**,LED 节点 **0.000 °C**(它的阻值到不了切换点),冷端 adc=800 处 **−0.163 °C**。

**一处有意与参考实现不同**(裁决过的,不是疏忽):

1. **分母用 `SAR_MAX - 1`**。配置里 `NTC SAR VALUE MAX = 1024` 是**满量程计数**(10 位),不是最大码值;参考实现里硬编码的 `1023` 是最大码值。`1024 - 1` 就是 `1023` —— 但写成「配置值减一」之后,一块声明 4096 的 12 位板子会自动得到 4095,而不是照样减 1 然后错。

**方向提示**(写反了不会报错,只会静静给出反的结论):**计数越大 = 越冷**。NTC 在分压的低侧,计数升高意味着 NTC 阻值升高,而热敏电阻阻值升高意味着温度降低。这块板上也印证了:LCD 节点读 ~664 是凉的(~28 °C),LED 节点读 ~371 是热的(~57 °C)。

### 加一个新项目

1. `cp tools/ntc_profiles/9660_P53_2G.ini tools/ntc_profiles/<项目名>.ini`
2. 按新板子的厂商配置改数值。**格式就是厂商自己的格式**,`KEY = value;` 和 `KEY: value` 都认,`#` 注释、引号路径、大小写随意 —— 厂商的原始配置文件基本可以整份丢进来。
3. `python tools/ntc_convert.py <csv> --profile <项目名>`

**profile 的文件名就是项目名**(不含 `.ini`);`--list-profiles` 列出来的就是可以填进 `--profile` 的值。

公式是共用的,**只有这些数值会变**。

#### 默认档:只有一份 profile 时才敢猜

不写 `--profile` 时,工具**只在 `ntc_profiles/` 下恰好一份 `.ini` 时**才拿它当默认档;有**两份及以上**就**报错退出并列出可选项**,不猜。

这条规则是 2026-09-21 加的,理由是 [../TODO.md](../TODO.md) §6.19 记下的那个风险:**换项目时忘了换 profile,会静静出一份用错常数的摄氏度** —— 数字看着很合理,下游没有任何东西能发现。工具表头的 `# profile=` 行能事后核对,但那是事后;拒绝猜才是事前。

所以今天只有 9660 一份时,行为与从前**逐字相同**;第二个项目的 ini 落进那个目录的那天,不指定 `--profile` 的命令会**当场失败**,而不是拿 9660 的常数算另一块板。

> `SHIPPED_PROFILE_NAME`(工具里写着本仓出厂档的那个常量)**永远不会**变成隐式回落 —— 一旦它当了回落,上面这道守卫在第二个 profile 进来的那一刻就失效了。

**每份 profile 要填哪些键** —— 前七行**缺任何一个就报错退出**:

| 类 | 键 | 单位 / 取值 | 作用 |
|---|---|---|---|
| 公式 | `NTC R` / `NTC R2` | **kΩ**(工具 ×1000) | 分压:`R_ntc = R_pull * adc / (SAR-1-adc)` |
| 公式 | `NTC SAR VALUE MAX` | 满量程**计数** | 分母用 `SAR - 1` |
| 公式 | `NTC B VALUE` / `NTC B VALUE2` | — | B 方程 |
| 公式 | `NTC RESISTANCE` / `NTC RESISTANCE2` | **kΩ**(工具 ×1000) | R0,25 °C 标称阻值 |
| 守卫 | `NTC1 PATH` / `NTC2 PATH` | 路径字符串 | 与 samples.csv 的 `# ntc_paths=` 比;**不一致只 warn** —— 常数仍然是对的,但该看一眼是不是套错了档 |
| 判定 | `NTC VALUE MIN` / `NTC VALUE MAX` | °C | 判 `oor`;超范围**只标不钳** |
| 开关 | `NTC OBTAIN TEMP WAY` | 必须 `1` | `0`(查表法)会被**拒绝**,不是猜着算 |
| 可选 | `NTC B VALUE COLD` / `COLD2` + `NTC B SWITCH R` | B 值 / B 值 / **Ω** | 两段 B,**三键同进同出**;只给一半 → 报错;都不给 = 单 B |
| 可选 | `NTC TEMP COMP` / `NTC1 TEMP COMP` / `NTC2 TEMP COMP` | °C | 补偿;逐通道 > 裸键 > `0` |
| 可选※ | `NTC COUNT` | 默认 `2` | 只有前两个通道会被换算 |
| 可选 | `PPTP ADC INVALID MIN` | 默认 `1000` | **厂商档里没有这个键**;≥ 它 → 不算温度 |

※ **2026-09-21 起出厂档做了精简**:`9660_P53_2G.ini` 只留**公式真正用到**的键(18 个),`NTC COUNT` 与裸 `NTC TEMP COMP` 虽然工具**仍然会读**,但出厂档里不再写 —— 它们对这块板子的值是默认值,写进去只是噪音。裸 `NTC TEMP COMP` 尤其该省:厂商档里那个 `20` 是**给没有逐通道键的板子**用的,这块板子的 `NTC1/NTC2 TEMP COMP` 都是 `0`,留着它会让读的人以为这里补了 20 °C。**厂商原始文件的全文存档在 `ntc_profiles/templates/`**,没有丢。

**命名规则**:裸键 = 通道 0(`ntc_lcd`),后缀 `2` = 通道 1(`ntc_led`)。成对的键**两个都必须给**。

**单位坑**:配置里所有电阻一律 **kΩ**,工具内部 ×1000 换成欧姆。照厂商文件的写法填就行,**别自己先换算成欧姆再填**。

**工具完全不读的键**(厂商文件里有,留着只为保住原件原貌):`NTC ERR DETECT`、`NTC CPU PATH`、`NTC CPU TEMP COMP`、`NTC BOOT START TYPE` / `NTC BOOT START TEMP`、`NTC RTM INDEX` / `NTC RTM INDEX2`。

**数值从哪来**:从**真正跑在板子上的那段实现**来(本档就是厂商的 `transformNTCToTemp` Java),因为它的常数是字面量、不读任何配置 —— 板子上跑出来的温度只可能来自那些字面量。厂商的配置文件是**第二来源**,用来交叉核对;两者不一致时以实现为准(D-64)。

> `ntc_profiles/templates/temp_template.ini` 是厂商原始配置的**存档**,原样保留(含中文注释与转写损伤),给「找开发确认固件到底该读哪些键」这场对话用。它在**子目录**里,而 `--list-profiles` 的 glob 不递归,所以它**看不见也选不着** —— 这是故意的:它没有冷端 B,拿它当 profile 会静默按旧规则换算这块板子。

**缺了会怎样**:表里前七行**缺任何一个 → 报错退出**(报错会指名是哪个键、哪份文件),不会当作 0 悄悄算下去;后四行的可选键缺失走默认值。分段 B 那三个键比较特殊:**同进同出**,只给一半也会**报错**,因为"半个分段"没有任何合理默认。

**还没实现的**:`NTC OBTAIN TEMP WAY = 0`(查表法)会**被拒绝并说明原因**,而不是拿公式硬套。要用查表法得先把厂商那张电阻-温度表弄进来。

### 自检

`--selftest` **85 项**断言,不需要设备也不需要数据文件。除了常规的解析/边界,有三项值得单独说:

- **25 °C 不变量**:在「NTC 阻值正好等于 R0」的那个计数上(由常数反解得出 `adc = R0*(SAR-1)/(R0+R_pull)`),公式**必须**给出精确的 25.00 °C。这是一个**非循环**的强断言 —— 它不是抄自本工具的输出,而是公式本身的一个固有点。
- **真值回归**:`REFERENCES` 表里是这块板子的真实读数,**两种规则的值都留着**(664 → 单 B 28.137578 / 两段 28.185747),断言打在**两段**那一列 —— 那才是厂商实现在做的事。重构让其中一个数字动了,就说明公式变了 —— 而公式是唯一不能意外改变的东西,因为归档的 csv 是永久的。
- **分段规则的边界**:用「冷端 B 故意设成荒诞值」的 profile 把切换点钉到**计数**上(442 不切、443 切),再用「两个 B 相等 ⇒ 分段 profile 必须逐位等于单 B profile」证明这个分支**只选 B、不做别的事**;另有一条把切换点放在某个计数算出的电阻上,验证比较是**严格大于**(`r > r` 为假)。反身验证过:把分段那两行注释掉,新断言里**红 9 条**(含 5 条真值回归)。

**默认档那三条**(v1.3.0 加,用临时目录造 0 / 1 / 2 份 profile 来驱动 `resolve_profile_name()`):目录**空** → 报错;**恰好一份** → 就用它(这条是**回归哨兵** —— 今天仓库里就是一份,它钉住"第二个项目进来之前行为一个字不变");**两份** → 报错,且报错信息里**两份的名字都出现**(否则用户没法照着填 `--profile`)。另有一条:**显式给了 `--profile` 就直接用它**,不吃目录里有什么 —— 这条防的是「守卫把正常的显式调用也拦了」。

自检里还有一条**带 bug 的输入**做守卫:`samples.csv` 表头里的 `ntc_unit=` 必须声明 `raw_adc`。否则一个已经换算过的文件会被**再换算一次**(28 °C 当成计数 28 喂进去,出来一个「很热的节点」,全程不报错)。这个守卫在写工具的第一轮就抓到了真 bug —— 厂商配置里 `NTC R2 = 4.7:` 的冒号写在**值后面**(该是 `;` 的位置),解析器一开始只容忍行尾的 `;`。

然后是一条**关于报错原因**的断言:一个**早于 NTC 通道**的归档文件(v2.13.0 之前、没有 `ntc_lcd` 列)**同时**缺列和缺 `ntc_unit=` 声明。两个检查都是纯函数,先跑哪一个只决定**打印哪一句理由** —— 所以顺序本身就是一条要被测的契约。先查单位会把它报成「这份文件没有声明单位」,把读的人引去找一个根本不该存在的东西。断言因此走 `main()` 而不是直接调检查函数:顺序住在 `main()` 里,那就得在 `main()` 上验。

**图的断言分三层,因为这三层的能力不一样**:

- **形状层不需要绘图库** —— `chart_series()` 是纯函数,而上面那些「诚实规则」全都住在它里面:缺读变 NaN 而不是被连过去、保持拍有线无点、超量程的读数既不成点也不消失、周期取中位数。这些在没装 matplotlib 的机器上照样全跑。
- **渲染层需要** —— 落盘的 PNG 有 PNG magic、体积不是一块空画布、深色主题渲染出的字节与浅色不同(证明它是**自己一套**色值,不是反相)。这一句**没装 matplotlib 时打印 SKIP,不算 PASS 也不算 FAIL** —— 一条被跳过的断言绝不能读起来像「图已经验过了」。
- **像素层(需要绘图库)** —— 把落盘的 PNG **读回来数像素**:在绘图区里数系列色的像素个数,量的就是这幅图
  「看起来有没有东西」。三条:「14.5 小时的跑曲线还在」(38388 px)、「**把点强行打开,曲线就塌了**」
  (227 px,169 倍 —— **这一条量的就是 D-69 那个 bug 本身**)、「短跑确实带着点画」;另有一条**量点径**,
  钉住「阈值所依据的那个直径」和「真正画出来的那个直径」是同一个。
  这一层是**唯一**能抓住 D-69 的层:数据对、artist 对、形状对,**坏的是光栅化那一步**,
  所以前两层全绿。见 [../docs/PITFALLS.md](../docs/PITFALLS.md) #56。
